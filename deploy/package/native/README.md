# Directory Services Portal @VERSION@: native deployment package

The portal without containers, for a Linux host with systemd, Java 21+ and (optionally) nginx.
Built @BUILD_DATE@ from @GIT_REVISION@.

```bash
tar xzf directory-services-portal-@VERSION@-native.tar.gz
cd directory-services-portal-@VERSION@-native
sudo ./install.sh
sudo vi /etc/directory-services-portal/portal.env     # LDAP connection, administrators
sudo systemctl restart directory-services-portal
```

The packaged nginx site serves plain HTTP on **127.0.0.1:8080, this host only** (`NGINX_LISTEN` in
`portal.env`): plain HTTP carries directory passwords and the session cookie in clear. Serve the
network over HTTPS (see below). `NGINX_LISTEN=8080` listens on every interface, for a TLS proxy on
another host; run `install.sh` again after changing it. A `portal.env` from an earlier release has
no `NGINX_LISTEN` and keeps listening on every interface, as before (the installer warns).

| Installed to | |
|---|---|
| `/opt/directory-services-portal/api` | the API (`directory-services-portal.jar`), run by systemd as user `dsp` on 127.0.0.1:3001 |
| `/opt/directory-services-portal/web` | the web client (static files) |
| `/etc/directory-services-portal/portal.env` | settings, documented; kept on upgrades |
| `/etc/directory-services-portal/proxy-secret` | the X.509 proxy secret (root and `dsp` only), generated once; `nginx-proxy-secret.conf` next to it is the copy nginx includes (root only) |
| `/etc/directory-services-portal/secrets-key` | the key webhook signing secrets are stored encrypted with (`DSP_SECRETS_KEY_FILE`; root and `dsp` only), generated by a new installation only, never replaced. Back it up apart from the data: without it the stored secrets can't be read. An upgraded `portal.env` without `DSP_SECRETS_KEY_FILE` keeps storing them unencrypted (`install.sh` says how to add a key) |
| `/var/lib/ens/directory-portal` | the ENS license (`ENS_LICENSE_FILE`, written by the license screen), this installation's id and the license revisions seen (`ENS_LICENSE_STATE_DIR`); keep it |
| `/var/lib/directory-services-portal` | data: configuration, audit log, analysis results (back this up) |
| `/etc/nginx/conf.d/directory-services-portal.conf` | serves the client on `NGINX_LISTEN` (new installs: 127.0.0.1:8080) and proxies `/api` (when nginx is installed) |

- Logs: `journalctl -u directory-services-portal -f` (`LOGGING_STRUCTURED_FORMAT_CONSOLE=ecs` in
  `portal.env` for JSON lines).
- The LDAP service account's password goes in `/etc/directory-services-portal/ldap-bind-password`
  (root and `dsp` only; `LDAP_BIND_PASSWORD_FILE` in `portal.env`), not in `portal.env`. A
  `portal.env` from an earlier release that sets `LDAP_BIND_PASSWORD` keeps working.
- The unit runs the API without capabilities or devices, with `SystemCallFilter=@system-service`,
  `RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX`, `ProtectSystem=strict` and `UMask=0077`.
- Health: `curl http://127.0.0.1:3001/readyz` (the directory answers and the audit log is
  writable) and `/livez`. For Prometheus set `MANAGEMENT_SERVER_PORT` (e.g. 9090) in `portal.env`:
  `/actuator/prometheus` and the probes are then served there, on 127.0.0.1
  (`MANAGEMENT_SERVER_ADDRESS`).
- License: without an ENS Solutions license only sign-in and the license screen work. Sign in as
  an administrator and upload it under *Administration > License* (`/admin/license`), which also
  shows the installation id to bind a license to; or copy it in with
  `sudo install -m 640 -o dsp -g dsp acme.lic /var/lib/ens/directory-portal/license.lic`.
  The paths are `ENS_LICENSE_FILE` / `ENS_LICENSE_STATE_DIR` in `portal.env` (the unit sets the
  same defaults); the directory must stay writable by `dsp`. With the shared database
  (`DSP_DATABASE_URL` in `portal.env`) the license is kept in the database and that file is read
  only on the first start: afterwards upload the license, or set `ENS_LICENSE=$(base64 -w0 acme.lic)`
  in `portal.env` and restart, which installs it unless a different usable license, or a newer
  revision of it, is installed already. The startup log line `License: ...` says what is in effect. For a trial, download an evaluation license from the ENS licensing portal.
  `ENS_LICENSE_MENU_VISIBLE=false` in `portal.env` hides the license page's menu entry (the page,
  and the ways to it while a license is missing, expiring or read-only, stay); default `true`.
- HTTPS: terminate TLS in nginx (add a `listen 443 ssl` server, or put a proxy in front) and set
  `ENS_COOKIE_SECURE=true`. The site sends the ENS security headers (CSP and others); HSTS when a
  proxy in front sends `X-Forwarded-Proto: https`; in your own `listen 443 ssl` server add
  `add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;`. For X.509 sign-in through nginx (`X509_SOURCE=header`,
  `X509_TRUSTED_PROXIES=127.0.0.1/32`, `X509_TRUSTED_CA_FILE`), see the installation guide:
  https://winllc.github.io/ens-apps-documentation/directory-services-portal/install/
  The location that proxies `/api` in that server must
  `include /etc/directory-services-portal/nginx-proxy-secret.conf;` (as the packaged site does) and
  set the certificate header itself (`proxy_set_header X-SSL-Client-Cert $ssl_client_escaped_cert;`):
  the API accepts a forwarded certificate only with the proxy secret, and does not start in header
  mode without it or without `X509_TRUSTED_CA_FILE`. Other local processes can reach
  127.0.0.1:3001 too, which is why the address alone is not trusted. To change the secret, write a
  new value to `proxy-secret` and run `install.sh` again (it rewrites nginx's copy), then restart
  the API.
- Single sign-on: set `PORTAL_PUBLIC_URL` (e.g. `https://portal.example.com`) and `PUBLIC_HOST`
  (its host[:port]) in `portal.env` and run `install.sh` again: it writes `PUBLIC_HOST` into the
  nginx site as `X-Forwarded-Host`, so a client's `Host` header can't change the redirect URI or
  SAML entity id. Behind your own web server, send that fixed host as `X-Forwarded-Host` and drop
  client `Forwarded`, `X-Forwarded-Prefix` and `X-Forwarded-Port` headers.
- With SELinux enforcing, nginx needs `setsebool -P httpd_can_network_connect 1` to reach the API.
- Upgrade: run the new package's `install.sh`; settings and data are kept. It generates the X.509
  proxy secret if there is none yet; restart the API afterwards
  (`systemctl restart directory-services-portal`).
